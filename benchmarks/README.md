# T8: один промпт и AulSabaq

Живой прогон: 24 ноября 2026. Сохранённые ответы и оценки: `results/2026-11-24/`.
Десять пар: пять ru, пять kk; математика, язык, познание мира; два или три класса; 45 минут.
Основная модель обеих сторон: OpenAI `gpt-6-luna`, взята из окружения, без списка запасных основных моделей.

## Метод

Один промпт получает запрос учителя и JSON-схему расписания и карточек. Он не получает алгоритм расписания,
численные нормы карточек и обратную связь валидатора. Его точный текст сохранён в `compare-prompts.bench.ts`.
AulSabaq выполняет обычную многошаговую генерацию: объяснения, содержание, проверки, повторы и корректуру.
Сравниваются только общие поля `LessonCoreSchema`, затем `validateLessonPlan()` и соответствие запросу.
Схема и алгоритм проверок соответствуют базовому коду коммита `6c6211a`.

Это сравнение двух способов подготовки урока, а не равного числа токенов, запросов или стоимости.
JSON-схема помогает одному промпту, но требования формата специфичны для нашего приложения.
Человек не оценивал методику, язык, пригодность заданий и точность оценки минут.
Проверка ответа в подсказке ищет буквальное совпадение, а не все способы раскрыть ответ.
При ошибке схемы дальнейшие инварианты не оцениваются; это не означает отсутствие ошибок в них.

В исходном `method.json` поле `verificationModel` читало неиспользуемую переменную и равно null.
Фактическая `OPENAI_FAST_MODEL` и reasoning не были записаны: полную идентичность всех вспомогательных
вызовов подтвердить по архиву нельзя. Исправлено только сохранение fastModel для будущих прогонов;
исторические метаданные не переписаны. Замеры API не доказывают время подготовки учителя.

## Результат

Все проверки: один промпт 0/10, продукт 7/10. Продукт дважды отказал с `invalid_plan`,
а в случае 5 вернул урок с мягким замечанием TIME: 14 минут практики на 23 минуты самостоятельной работы.
Это предусмотренный текущим кодом fallback, но строгую проверку обеспеченности такой урок не прошёл.
Нельзя считать все восемь возвращённых уроков полностью валидными.

Медианное время всех попыток: 31,0 с и 134,2 с соответственно, включая неудачи и дополнительную
работу продукта над объяснениями. Подробная таблица: `docs/TEST_LOG.md`, проверка 12.

## Повторить оценку без сети и платных запросов

```sh
node node_modules/vitest/vitest.mjs run --config benchmarks/vitest.config.mts benchmarks/replay-results.bench.ts
```

Проверяются исходные JSON и записанные результаты всех десяти пар. У двух отказов продукта
нет конечного урока: их причины сохранены в `N-result.json`, содержимое не восстановлено и не придумано.
Обычный `npm test` не запускает эксперименты.

## Новый платный прогон

Только при отдельном решении повторить эксперимент, с настроенным `.env.local`:

```sh
RUN_LIVE_BENCHMARK=on BENCHMARK_OUTPUT=/private/tmp/aulsabaq-t8-new node --env-file=.env.local node_modules/vitest/vitest.mjs run --config benchmarks/vitest.config.mts benchmarks/compare-prompts.bench.ts
```

Ключи не сохраняются, база школы не используется. Без явного флага живой тест пропускается.
