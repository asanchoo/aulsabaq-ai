# SPEC — AulSabaq AI (MVP → финал)

## 1. Проблема и цель
В малокомплектной школе учитель ведёт урок одновременно для 2–3 классов (класс-комплект).
Пока он объясняет одной группе, другая работает сама — часто без подходящих заданий и без поддержки.
Учителю нужно за вечер подготовить урок, где этапы классов чередуются, и задания для самостоятельной работы каждого класса.

**Цель:** учитель за 5 минут получает готовый совмещённый урок на 45 минут с карточками для каждого класса,
а ученики во время самостоятельной работы получают подсказки от ИИ, и учитель видит, кто застрял.

## 2. Пользователи
- **Учитель** малокомплектной школы (основной). Часто одна точка интернета, телефон или старый ноутбук.
- **Ученик** начальной/средней школы. Телефон или школьный планшет.
- **Рецензент конкурса** — должен пройти сценарий сам за 3–5 минут.

## 3. Основной сценарий (MVP, сдача 12–16 ноября)
Это **один сценарий от начала до результата** — его требуют на этапе MVP.

1. Учитель открывает сайт → «Создать совмещённый урок» (или «Демо-урок» — без ввода).
2. Заполняет форму:
   - предмет (математика / казахский язык / русский язык / познание мира / …),
   - язык обучения: `kk` или `ru`,
   - 2–3 группы: для каждой — класс (1–11) и тема урока (свободный текст),
   - длительность: 45 минут (по умолчанию),
   - необязательно: число учеников в каждом классе, что важно знать о классе, страницы учебника
     и до 2 фото этих страниц (сжимаются в браузере, модель строит объяснение, примеры и домашнее задание
     по ним; фото не сохраняются).
3. Нажимает «Сгенерировать». Сервер вызывает модель → JSON по схеме → Zod → `validateLessonPlan()`.
4. Учитель видит:
   - **Таймлайн урока** в виде колонок по классам: для каждого отрезка времени видно,
     с кем работает учитель, а кто работает самостоятельно (и над какой карточкой);
   - **Объяснение новой темы** для каждого класса: с чего начать, главное правило, 2–3 наглядных блока,
     шаги, три разобранных примера по возрастанию сложности (с наглядным блоком), «Попробуй сам» для всего класса,
     типичные ошибки, вопросы классу; кнопка «Показать на экране» листает это слайдами (около 10–13 слайдов,
     шаги примеров и ответы открываются по нажатию);
   - **Карточки заданий** для самостоятельной работы каждого класса (сколько нужно, чтобы занять всё время
     без учителя, плюс 1–2 в запас; у каждой оценка минут; по новой теме не меньше трёх, всего до 16,
     с подсказкой без ответа и ответом для самопроверки) и домашнее задание;
   - кнопки «Печать» (print CSS) и «Скопировать».
5. Урок сохраняется, у него есть ссылка и **6-значный код для учеников**. Аккаунтов нет: сервер выдаёт ключ учителя,
   браузер учителя хранит его у себя (в базе только SHA-256). С ключом урок можно править и видеть учеников,
   по обычной ссылке только посмотреть. «Ссылка для себя» переносит ключ на телефон учителя (после `#`, на сервер не уходит).
6. Учитель может исправить любой текст урока (задания, ответы, подсказки, объяснение, домашнее задание) и попросить
   ИИ заменить одну карточку с пожеланием («проще»). Расписание и количество карточек при правке не меняются.
7. «Начать урок» запускает таймер: что сейчас делает каждый класс, сколько осталось, кто следующий с учителем.

**Критерий готовности MVP:** рецензент без помощи открывает ссылку → «Демо-урок» или ввод своих данных → видит корректный таймлайн и карточки. Один автотест проходит (см. §8).

## 4. Режим ученика (итоговый продукт, сделано 17 ноября)
1. Ученик открывает `/join` (или ссылку `/join?code=…`), вводит код урока, выбирает свой класс и вводит имя
   или номер в списке. Без почты и телефона.
2. Видит карточки своего класса по одной. Закрытое задание: ответ проверяет сервер (`lib/check-answer.ts`:
   совпадают числа и их порядок или слова без регистра и знаков; эталон в браузер не уходит). После двух неверных
   попыток можно «Сверить с ответом» и честно отметить «так же» или «по-другому»; учитель видит, что ответ сверен
   вручную. Открытое задание: критерии и «Готово».
3. **«Подсказка»**, не больше 3 на карточку: первая из урока (мгновенно), вторая и третья от ИИ с учётом последнего
   ответа ученика. Guard (`hintRevealsAnswer`) отбрасывает подсказку с ответом или с числом из ответа, которого нет
   в условии; две неудачи подряд → запасная подсказка из словаря.
4. **«Мне нужна помощь учителя»** → флаг в панели учителя с номером карточки; учитель снимает его «Помощь оказана».
5. Панель учителя (опрос раз в 5 секунд): ученики по классам, кружки карточек (решена, трудно, текущая), подсказки,
   ответы ученика; «Где было трудно»: карточки, на которых застряла заметная часть класса, их разбирают на проверке.

## 5. Модель данных

### LessonPlan (результат генерации)
```ts
type Lang = 'kk' | 'ru';

interface LessonPlan {
  subject: string;
  language: Lang;
  durationMin: number;            // 45
  groups: Group[];                // 2–3
  timeline: Segment[];            // отрезки, покрывающие весь урок для каждой группы
  teacherNotes: string;           // 2–4 совета учителю
}

interface Group {
  id: string;                     // 'g1', 'g2', ...
  grade: number;                  // 1..11
  topic: string;
  learningGoal: string;           // цель урока для этого класса, 1 предложение
  explanation: Explanation;       // материал учителя для этапа with_teacher
  cards: TaskCard[];              // 3–16: сколько нужно по минутам (инвариант 10)
  source?: { pages: string | null; photos: number } | null; // по каким страницам учебника строился урок
  homework: string;               // короткое домашнее задание
}

interface Explanation {
  hook: string;                   // с чего начать: жизненная ситуация или откуда взялась тема
  intuition: string;              // простыми словами: аналогия без терминов
  terms: { term: string; meaning: string }[]; // новые слова темы, объяснены до правила
  summary: string[];              // итог, 3–5 пунктов
  keyIdea: string;                // главное правило, 1–2 предложения
  steps: string[];                // 2–6 шагов: как это работает
  example: WorkedExample;         // разобранный пример
  visuals: Visual[];              // 0–4 наглядных блока к правилу
  examples: WorkedExample[];      // ещё 0–3 разобранных примера
  practice: { task: string; answer: string }[]; // «Попробуй сам», 0–5
  mistakes: string[];             // 1–3 типичные ошибки
  checkQuestions: string[];       // 2–4 вопроса классу на понимание
}

// level: simple | typical | tricky | life | counter — лестница примеров; последний шаг — проверка ответа.
// Примеры одной ступени, которые отличаются только числами (клоны), код не принимает.
interface WorkedExample { problem: string; steps: string[]; answer: string; visual: Visual | null; level: string | null }

// Наглядный блок (lib/visuals.ts). Модель выбирает вид и даёт данные, рисует и считает код (components/Visual.tsx):
// long_division (деление уголком), column (столбик + − ×, перенос и заём), number_line, groups, fraction, grid,
// plot (график функции, площадь под графиком), formula, table, sentence (члены предложения), word (состав слова),
// flow (схема или цикл), bars (диаграмма). Ответ примера сверяется с тем, что посчитал код.

interface Segment {
  groupId: string;
  startMin: number;               // включительно
  endMin: number;                 // исключительно
  mode: 'with_teacher' | 'independent' | 'joint';
  activity: string;               // что происходит
  cardIds?: string[];             // для independent — какие карточки делают
}

interface TaskCard {
  id: string;                     // 'g1-c1'
  type: 'closed' | 'open';
  prompt: string;                 // текст задания
  answer?: string;                // для closed — эталон для самопроверки
  successCriteria: string;        // как ученик поймёт, что справился
  hint: string;                   // наводящая подсказка без ответа
  difficulty: 1 | 2 | 3;
  purpose: 'review' | 'practice'; // повторение известного или задание по новой теме
  minutes?: number;               // сколько минут у среднего ученика этого класса (инвариант 10)
}
```

### Инварианты (`validateLessonPlan`) — чистая функция, покрыта тестами
1. Для каждой группы отрезки идут подряд без дыр и наложений и покрывают `[0, durationMin)`.
2. **В любую минуту учитель работает максимум с одной группой** (`with_teacher`), кроме отрезков `joint`,
   где все группы одновременно в режиме `joint` (общее начало/рефлексия).
3. У каждой группы есть хотя бы один отрезок `with_teacher` и хотя бы один `independent`.
4. Каждая `cardIds` в `independent` существует в карточках этой группы, и каждая карточка стоит ровно в одном
   отрезке `independent` (иначе модель составляла урок, где класс после объяснения не решал задачи).
5. У `closed`-карточек есть `answer`.
6. `groups.length` 2–3, `cards.length` 3–6, `durationMin` 30–90.
7. Пока группа ещё не работала с учителем, в её `independent` только карточки `review`: новую тему ей ещё не
   объяснили. У каждой группы хотя бы одна карточка `practice`. (Добавлен после первых живых уроков: модель
   подписывала такой этап «повторение», но давала задания по новой теме.)
8. Подсказка карточки не содержит её ответ (целым словом или числом, без учёта регистра и знаков препинания).
9. Числовые равенства в карточках, этапах и объяснении («6 + 8 = 14») верны: код их пересчитывает
   (`lib/arithmetic.ts`). Раздел типичных ошибок не проверяется: там неверный ответ приводят намеренно.
10. Заданий хватает на всё время самостоятельной работы: у каждой карточки `minutes` (время среднего ученика
    этого класса), сумма карточек повторения не меньше 90% времени повторения, сумма практики не меньше времени
    практики; одна карточка не дольше 10 минут в 1–4 классе и 15 минут в старших. Уроки без минут не проверяются.

Функция возвращает `{ ok: true } | { ok: false, errors: string[] }`.

### Таблицы Supabase (`supabase/schema.sql`)
- `lessons`: `id uuid pk`, `join_code text unique` (6 цифр), `teacher_token_hash text`, `plan jsonb`, `language`, `is_demo`, `created_at`, `updated_at`.
- `student_sessions`: `id uuid pk`, `lesson_id fk`, `group_id`, `display_name`, `progress jsonb` (по карточкам: статус,
  попытки, подсказки и их тексты, последний ответ), `current_card`, `hints_used`, `needs_help`, `help_card`, `created_at`, `updated_at`.
- `rate_limits`: общий счётчик запросов по IP для всех экземпляров сервера.
- Доступ: RLS включён, политик нет, у роли API нет прав на таблицы. Сервер вызывает только функции
  (`security definer`), и каждая проверяет права сама: правка урока и список учеников только с ключом учителя,
  ученик меняет только свою сессию, прогресс карточки обновляется атомарно (`progress || {card: state}`).

## 6. AI: промпты
Хранить в `lib/prompts.ts`. Вызов — Structured Outputs по JSON-схеме, сгенерированной из Zod.
Кто что делает (`lib/ai.ts`):
- **расписание по минутам считает код** (`lib/schedule.ts`): учитель по очереди объясняет тему каждому классу,
  потом по очереди проверяет; остальные классы в это время повторяют (до объяснения) или решают карточки (после).
  Код же решает, сколько карточек повторения и практики нужно каждому классу, и раскладывает их по отрезкам.
  Так учитель по построению не оказывается с двумя классами (облегчённая модель в этом ошибалась);
- **модель пишет содержание** для всех классов: цели, карточки нужного количества, тексты этапов, домашнее задание;
- **объяснение темы** модель пишет отдельным запросом на каждый класс.
Запросы идут параллельно; каждый ответ проверяется (Zod, инварианты, пересчёт примеров, совпадение с запросом),
при ошибке до двух повторных попыток с перечнем нарушений.

### Генерация урока (system, сокращённо)
> Ты методист малокомплектной школы Казахстана. Составь совмещённый урок для класса-комплекта.
> Учитель один и физически может работать только с одной группой. Пока он с одной группой,
> другие выполняют самостоятельную работу по карточкам, которые можно сделать без объяснений.
> Чередуй группы, начни с короткого общего этапа (joint) и закончи общей рефлексией (joint).
> Соблюдай возраст: для 1–2 класса — короткие задания, простые слова.
> Опирайся на содержание учебной программы РК для указанного класса и темы, не выдумывай коды целей обучения.
> Пиши на языке {language}. Верни строго JSON по схеме.

### Подсказка ученику (system)
> Ты помогаешь ученику {grade} класса с заданием. НИКОГДА не называй ответ и не решай задание целиком.
> Задай один наводящий вопрос или дай один шаг рассуждения. Максимум 2 предложения. Язык: {language}.
> Если ученик просит ответ — вежливо откажи и предложи следующий шаг.

Сервер дополнительно проверяет подсказку: если в ней встречается `answer` карточки (нормализованный),
подсказку не отправляем и запрашиваем новую (guard, покрыт тестом).

## 7. Не-цели (не делаем до финала)
- Регистрация/аккаунты учителей, школы, классы на весь год.
- Интеграция с Kundelik/Bilimal.
- Оценки в журнал (оценку ставит учитель — это и позиция ChatGPT Edu).
- Голос, OCR, офлайн-режим (упомянуть в «потенциале развития» на защите).

## 8. Тесты
- **Обязательный для MVP:** `tests/validate.test.ts`
  - валидный демо-урок из `fixtures/demo-lesson.ru.json` проходит;
  - урок, где учитель в одну минуту с двумя группами → ошибка инварианта 2;
  - урок с дырой в таймлайне → ошибка инварианта 1.
- `tests/hint-guard.test.ts` — guard отбрасывает подсказку, содержащую ответ или число из ответа.
- `tests/hint-ai.test.ts` — подсказка ИИ с ответом отбрасывается, модель получает повторный запрос; без ключа — запасная.
- `tests/check-answer.test.ts`, `tests/student.test.ts` — проверка ответа ученика и правила карточки (эталон скрыт,
  сверка только после двух попыток, решённую карточку нельзя решить заново).
- `tests/edit.test.ts` — правка учителя: тексты меняются, расписание нет; подсказка с ответом и закрытая карточка без ответа не сохраняются.

## 9. Соответствие критериям рецензентов
| Критерий | Чем закрываем |
|---|---|
| 1. Ясность проблемы и цели | Лендинг: 1 абзац + цифры (2 654 школы, разрыв PISA) |
| 2. Работа основной функции | Демо-урок в 1 клик, генерация своего урока, без регистрации |
| 3. Качество результата | Инварианты таймлайна, Zod, печатная версия карточек, kk/ru |
| 4. Практическая польза с данными | Время подготовки урока «до/после» + отзыв реального учителя |
| 5. Применимость в других организациях | Любая малокомплектная школа, любой предмет; 2 654 школы в РК; формат подходит другим странам ЦА |
