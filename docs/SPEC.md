# SPEC — AulSabaq AI (MVP → финал)

## 1. Проблема и цель
В малокомплектной школе учитель ведёт урок одновременно для 2–3 классов (класс-комплект).
Пока он объясняет одной группе, другая работает сама — часто без подходящих заданий и без поддержки.
Учителю нужно за вечер подготовить урок, где этапы классов чередуются, и задания для самостоятельной работы каждого класса.

**Цель:** учитель за 5 минут получает готовый совмещённый урок на 45 минут с карточками для каждого класса,
а ученики во время самостоятельной работы получают подсказки от ИИ, и учитель видит, кто застрял.

## 2. Пользователи
- **Учитель** малокомплектной школы (основной). Часто одна точка интернета, телефон или старый ноутбук.
- **Ученик** начальной/средней школы. Телефон или школьный планшет.
- **Рецензент конкурса** — должен пройти сценарий сам за 3–5 минут.

## 3. Основной сценарий (MVP, сдача 12–16 ноября)
Это **один сценарий от начала до результата** — его требуют на этапе MVP.

1. Учитель открывает сайт → «Создать совмещённый урок» (или «Демо-урок» — без ввода).
2. Заполняет форму:
   - предмет (математика / казахский язык / русский язык / познание мира / …),
   - язык обучения: `kk` или `ru`,
   - 2–3 группы: для каждой — класс (1–11) и тема урока (свободный текст),
   - длительность: 45 минут (по умолчанию),
   - необязательно: число учеников в каждом классе.
3. Нажимает «Сгенерировать». Сервер вызывает модель → JSON по схеме → Zod → `validateLessonPlan()`.
4. Учитель видит:
   - **Таймлайн урока** в виде колонок по классам: для каждого отрезка времени видно,
     с кем работает учитель, а кто работает самостоятельно (и над какой карточкой);
   - **Объяснение новой темы** для каждого класса: с чего начать, главное правило, шаги, разобранный пример,
     типичные ошибки, вопросы классу; кнопка «Показать на экране» листает это как слайды;
   - **Карточки заданий** для самостоятельной работы каждого класса (5–6 заданий, с подсказкой без ответа
     и ответом для самопроверки) и домашнее задание;
   - кнопки «Печать» (print CSS) и «Скопировать».
5. Урок сохраняется, у него есть ссылка и **6-значный код для учеников**.

**Критерий готовности MVP:** рецензент без помощи открывает ссылку → «Демо-урок» или ввод своих данных → видит корректный таймлайн и карточки. Один автотест проходит (см. §8).

## 4. Режим ученика (к итоговому продукту, 18–20 ноября)
1. Ученик открывает `/join`, вводит код урока, выбирает свой класс и вводит имя (или номер в списке).
2. Видит карточки своего класса по одной. Вводит ответ → проверка (точное совпадение/числовое сравнение для закрытых заданий; для открытых — «отметить как выполнено»).
3. Кнопка **«Подсказка»** → ИИ задаёт наводящий вопрос по этому заданию, **без ответа**. Не более 3 подсказок на задание.
4. Кнопка **«Мне нужна помощь учителя»** → флаг в панели учителя.
5. Учитель на странице урока видит список учеников: на какой карточке, сколько подсказок, флаг «нужна помощь». Обновление каждые 5 сек (polling) или Supabase Realtime.

## 5. Модель данных

### LessonPlan (результат генерации)
```ts
type Lang = 'kk' | 'ru';

interface LessonPlan {
  subject: string;
  language: Lang;
  durationMin: number;            // 45
  groups: Group[];                // 2–3
  timeline: Segment[];            // отрезки, покрывающие весь урок для каждой группы
  teacherNotes: string;           // 2–4 совета учителю
}

interface Group {
  id: string;                     // 'g1', 'g2', ...
  grade: number;                  // 1..11
  topic: string;
  learningGoal: string;           // цель урока для этого класса, 1 предложение
  explanation: Explanation;       // материал учителя для этапа with_teacher
  cards: TaskCard[];              // 3–6 (промпт просит 5–6)
  homework: string;               // короткое домашнее задание
}

interface Explanation {
  hook: string;                   // с чего начать: жизненная ситуация или откуда взялась тема
  keyIdea: string;                // главное правило, 1–2 предложения
  steps: string[];                // 2–6 шагов: как это работает
  example: { problem: string; steps: string[]; answer: string }; // разобранный пример
  mistakes: string[];             // 1–3 типичные ошибки
  checkQuestions: string[];       // 2–4 вопроса классу на понимание
}

interface Segment {
  groupId: string;
  startMin: number;               // включительно
  endMin: number;                 // исключительно
  mode: 'with_teacher' | 'independent' | 'joint';
  activity: string;               // что происходит
  cardIds?: string[];             // для independent — какие карточки делают
}

interface TaskCard {
  id: string;                     // 'g1-c1'
  type: 'closed' | 'open';
  prompt: string;                 // текст задания
  answer?: string;                // для closed — эталон для самопроверки
  successCriteria: string;        // как ученик поймёт, что справился
  hint: string;                   // наводящая подсказка без ответа
  difficulty: 1 | 2 | 3;
  purpose: 'review' | 'practice'; // повторение известного или задание по новой теме
}
```

### Инварианты (`validateLessonPlan`) — чистая функция, покрыта тестами
1. Для каждой группы отрезки идут подряд без дыр и наложений и покрывают `[0, durationMin)`.
2. **В любую минуту учитель работает максимум с одной группой** (`with_teacher`), кроме отрезков `joint`,
   где все группы одновременно в режиме `joint` (общее начало/рефлексия).
3. У каждой группы есть хотя бы один отрезок `with_teacher` и хотя бы один `independent`.
4. Каждая `cardIds` в `independent` существует в карточках этой группы, и каждая карточка стоит ровно в одном
   отрезке `independent` (иначе модель составляла урок, где класс после объяснения не решал задачи).
5. У `closed`-карточек есть `answer`.
6. `groups.length` 2–3, `cards.length` 3–6, `durationMin` 30–90.
7. Пока группа ещё не работала с учителем, в её `independent` только карточки `review`: новую тему ей ещё не
   объяснили. У каждой группы хотя бы одна карточка `practice`. (Добавлен после первых живых уроков: модель
   подписывала такой этап «повторение», но давала задания по новой теме.)
8. Подсказка карточки не содержит её ответ (целым словом или числом, без учёта регистра и знаков препинания).
9. Числовые равенства в карточках, этапах и объяснении («6 + 8 = 14») верны: код их пересчитывает
   (`lib/arithmetic.ts`). Раздел типичных ошибок не проверяется: там неверный ответ приводят намеренно.

Функция возвращает `{ ok: true } | { ok: false, errors: string[] }`.

### Таблицы Supabase (`supabase/schema.sql`)
- `lessons`: `id uuid pk`, `join_code text unique`, `plan jsonb`, `language text`, `created_at timestamptz`.
- `student_sessions`: `id uuid pk`, `lesson_id fk`, `group_id text`, `display_name text`, `current_card text`, `hints_used int`, `needs_help bool`, `updated_at`.
- `answers`: `id`, `session_id fk`, `card_id`, `answer text`, `correct bool null`, `created_at`.
- RLS: чтение урока по `join_code`; запись сессии только своей (MVP: доступ через серверные роуты с service key, клиент напрямую в БД не ходит).

## 6. AI: промпты
Хранить в `lib/prompts.ts`. Вызов — Structured Outputs по JSON-схеме, сгенерированной из Zod.
Урок собирается из параллельных запросов (`lib/ai.ts`): расписание с карточками для всех классов
и отдельное объяснение темы для каждого класса. У каждого запроса своя проверка и до двух повторных попыток.

### Генерация урока (system, сокращённо)
> Ты методист малокомплектной школы Казахстана. Составь совмещённый урок для класса-комплекта.
> Учитель один и физически может работать только с одной группой. Пока он с одной группой,
> другие выполняют самостоятельную работу по карточкам, которые можно сделать без объяснений.
> Чередуй группы, начни с короткого общего этапа (joint) и закончи общей рефлексией (joint).
> Соблюдай возраст: для 1–2 класса — короткие задания, простые слова.
> Опирайся на содержание учебной программы РК для указанного класса и темы, не выдумывай коды целей обучения.
> Пиши на языке {language}. Верни строго JSON по схеме.

### Подсказка ученику (system)
> Ты помогаешь ученику {grade} класса с заданием. НИКОГДА не называй ответ и не решай задание целиком.
> Задай один наводящий вопрос или дай один шаг рассуждения. Максимум 2 предложения. Язык: {language}.
> Если ученик просит ответ — вежливо откажи и предложи следующий шаг.

Сервер дополнительно проверяет подсказку: если в ней встречается `answer` карточки (нормализованный),
подсказку не отправляем и запрашиваем новую (guard, покрыт тестом).

## 7. Не-цели (не делаем до финала)
- Регистрация/аккаунты учителей, школы, классы на весь год.
- Интеграция с Kundelik/Bilimal.
- Оценки в журнал (оценку ставит учитель — это и позиция ChatGPT Edu).
- Голос, OCR, офлайн-режим (упомянуть в «потенциале развития» на защите).

## 8. Тесты
- **Обязательный для MVP:** `tests/validate.test.ts`
  - валидный демо-урок из `fixtures/demo-lesson.ru.json` проходит;
  - урок, где учитель в одну минуту с двумя группами → ошибка инварианта 2;
  - урок с дырой в таймлайне → ошибка инварианта 1.
- К финалу: `tests/hint-guard.test.ts` — guard отбрасывает подсказку, содержащую ответ.

## 9. Соответствие критериям рецензентов
| Критерий | Чем закрываем |
|---|---|
| 1. Ясность проблемы и цели | Лендинг: 1 абзац + цифры (2 654 школы, разрыв PISA) |
| 2. Работа основной функции | Демо-урок в 1 клик, генерация своего урока, без регистрации |
| 3. Качество результата | Инварианты таймлайна, Zod, печатная версия карточек, kk/ru |
| 4. Практическая польза с данными | Время подготовки урока «до/после» + отзыв реального учителя |
| 5. Применимость в других организациях | Любая малокомплектная школа, любой предмет; 2 654 школы в РК; формат подходит другим странам ЦА |
