## Этап 4. Доработка до 26 ноября (решение автора 24 ноября)

**Почему.** На встрече 24 ноября организатор сказал:
- до 26 ноября проекты можно дорабатывать;
- проверяют с телефона и нажимают все кнопки;
- проект должен быть сделан с помощью ChatGPT Edu (Codex или чат в workspace «ChatGPT Edu — Startup Ecosystem»),
  и это нужно прописать в паспорте;
- учителя сами делают уроки одним промптом, поэтому продукт должен закрывать боль, которую одним промптом не закрыть.

**Главная мысль.** Одним промптом в ChatGPT можно получить объяснение и карточки. Нельзя получить урок, который
идёт сам: расписание для трёх классов, которое считает и проверяет код, ученики с телефонов, подсказки без ответа,
«кто застрял» и итоги урока. Всё это у нас есть, но рецензент проверяет один, с одного устройства, и видит в основном
генератор. Задачи ниже показывают и усиливают то, что одним промптом не сделать.

### Правила для каждой задачи (Codex, Claude Code, автор)
- Одна задача = одна ветка и один PR. Задачи с одинаковыми файлами не делать параллельно (колонка «Зависит»).
- Перед кодом прочитать `AGENTS.md` целиком и нужный раздел `docs/SPEC.md`.
- Все строки интерфейса в `lib/i18n.ts` на ru и kk. В текстах UI без длинных тире и эмодзи.
- Кнопки только `.btn-primary` и `.btn-secondary`, цвета режимов только из `components/modes.ts`.
- Демо-урок и путь рецензента (`docs/REVIEWER_GUIDE.md`) работают без ключей модели и без автора.
- Готово, когда проходят `npm run lint && npm run typecheck && npm test`, а на новые чистые функции есть тесты.
- В описании PR коротко: что сделано, что не сделано, риски. Ключи и `.env.local` не трогать.
- Изменения базы (`supabase/schema.sql`) Codex только пишет. Применяет к Supabase автор или Claude Code
  через миграцию, до слияния PR.

**T2. Навигация по странице урока на телефоне.** Страница урока на телефоне около 60 экранов.
- Файлы: `components/LessonView.tsx` (разделы `#timeline`, `#explain`, `#cards`), `components/TeacherWorkspace.tsx`.
- Липкая полоса под шапкой: «Ход урока / Объяснение / Карточки / Ученики» (последняя, если урок в базе).

**T3. Таймер для учителя у доски.**
- Файл: `components/LessonRunner.tsx`.
- Смена этапа у любого класса: короткий сигнал (Web Audio, без файлов) и вибрация, где есть. Есть кнопка
  «Звук вкл/выкл», выбор запоминается в localStorage.
- Пока таймер идёт, экран не гаснет (Screen Wake Lock API). Если браузер не умеет, молча работаем без этого.
- «Закончить» и «Заново» спрашивают подтверждение.
- Новая просьба о помощи в `components/StudentsPanel.tsx`: тот же сигнал и счётчик в заголовке вкладки, «(2) …».

**T4. «Кому помочь сейчас».** Учитель один на три класса и не знает, к кому идти первым.
- Новая чистая функция `lib/help-queue.ts` с тестами `tests/help-queue.test.ts`. На входе ученики панели
  (как в `StudentsPanel.tsx`), план урока и минута урока (если таймер идёт).
- На выходе упорядоченный список с причиной для каждого:
  - просит помощи (дольше ждёт, тем выше);
  - 3 и больше неверных попыток на одной карточке;
  - нет ответа дольше 4 минут, пока класс работает сам;
  - половина класса застряла на одной карточке: подойти ко всему классу.
- Учитывать расписание: если учитель сейчас с другим классом, показать, через сколько минут он свободен.
- В панели блок «Кому помочь сейчас» над списком учеников: 3 первых пункта, причина простыми словами.

**T5. Демо-класс для рецензента.** Рецензент проверяет один и не видит живую часть.
- На странице демо-урока (копия демо с кодом) кнопка «Запустить демо-класс».
- В панели появляются 6–9 вымышленных учеников разных классов. За 2–3 минуты они решают карточки, ошибаются,
  берут подсказки, один зовёт на помощь. Панель, «Кому помочь сейчас» (T4) и «Где было трудно» оживают.
- Всё в браузере, без записи в базу. Генератор событий: чистая функция с зерном (повторяемо) и тестом.
- Над панелью ясная надпись: «Демо-класс: это имитация, настоящих учеников здесь нет» (правило M9).
  Кнопка «Остановить демо-класс». Настоящие ученики, если вошли, показываются как обычно.

**T6. Итоги урока и совет на завтра.**
- Кнопка «Итоги урока» после «Закончить» или в панели учеников.
- По каждому классу: сколько учеников, сколько карточек решено, 3 самые трудные карточки (доля неверных
  попыток), кто звал на помощь и по какой карточке.
- Совет на завтра, его считает код, не ИИ. Например: «4 класс: начать с повторения деления с остатком, 3 из 5
  ошиблись в карточке 4». Чистая функция с тестами.
- «Распечатать» и «Скачать CSV» (имя, класс, решено, подсказок, помощь). Оценку ставит учитель, мы её не считаем.
- Данные: те же, что у панели (`/api/lessons/[id]/students`, функция `lesson_sessions`).

**T7. Ученики идут по таймеру учителя.** Сейчас таймер живёт только в браузере учителя.
- База: в `lessons` поля `started_at timestamptz`, `paused_at timestamptz`. Функция `set_run(p_id, p_token_hash,
  p_started_at, p_paused_at)` с проверкой ключа учителя. `get_session` и `find_lesson_by_code` отдают эти поля.
- `LessonRunner` пишет старт, паузу и сдвиги на сервер.
- Ученик видит сверху «Сейчас: работаешь сам, карточки 1–6» или «Сейчас: учитель с твоим классом, слушай».
  Карточки новой темы открываются после объяснения его классу (минуты из расписания `lib/schedule.ts`).
- Если таймер не запущен, всё как сейчас.
